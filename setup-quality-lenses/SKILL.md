# Setup Quality Lenses

Intelligently set up the codebase-quality-lenses library in a project with optimal configuration based on detected tools and project structure.

## Overview

This skill will:
1. Detect project type, language, and structure
2. Scan for available quality tools (linters, type checkers, test runners)
3. Install the quality-lens CLI globally if not present
4. Generate an optimal `quality-lens.yaml` configuration
5. Initialize GitHub Actions workflow (optional)
6. Run a test to verify setup
7. Report unsupported tools and suggest filing issues

## Detection Strategy

### 1. Identify Project Languages

Check for language indicators:

**JavaScript/TypeScript:**
- `package.json`, `tsconfig.json`, `*.ts`, `*.tsx`, `*.js`, `*.jsx`

**Python:**
- `setup.py`, `pyproject.toml`, `requirements.txt`, `*.py`

**Go:**
- `go.mod`, `go.sum`, `*.go`

**Rust:**
- `Cargo.toml`, `Cargo.lock`, `*.rs`

**Monorepo Detection:**
- Check for workspace configuration in `package.json`, `pnpm-workspace.yaml`, `lerna.json`
- Check for multiple `package.json` files

### 2. Detect Available Quality Tools

For each detected language, check for:

**JavaScript/TypeScript:**
- ESLint: `devDependencies.eslint`, `eslintrc.*`, `eslint.config.*`
- TypeScript: `devDependencies.typescript`, `tsconfig.json`
- Prettier: `devDependencies.prettier`, `.prettierrc.*`
- Jest: `devDependencies.jest`, `jest.config.*`
- Vitest: `devDependencies.vitest`, `vitest.config.*`
- Bun Test: `bun.lockb`, `bunfig.toml`
- Knip: `devDependencies.knip`, `knip.json`
- Biome: `devDependencies.@biomejs/biome`, `biome.json`
- Alexandria: `devDependencies.@principal-ai/alexandria-cli`

**Python:**
- Ruff: `pyproject.toml` with `[tool.ruff]`, `ruff.toml`
- MyPy: `mypy.ini`, `pyproject.toml` with `[tool.mypy]`
- Pytest: `pytest.ini`, `pyproject.toml` with `[tool.pytest]`
- Black: `pyproject.toml` with `[tool.black]`
- Pylint: `.pylintrc`, `pyproject.toml` with `[tool.pylint]`

**Rust:**
- Clippy: Always available with Rust installation
- Rustfmt: `rustfmt.toml`, `.rustfmt.toml`
- Cargo Test: `Cargo.toml` with tests

**Go:**
- golangci-lint: `.golangci.yml`, `.golangci.yaml`
- go vet: Always available with Go installation
- go test: `*_test.go` files

### 3. Check for Existing Scripts

Parse `package.json` scripts or Makefile for existing quality commands:
- `lint`, `test`, `typecheck`, `format`, `docs`, etc.

## Configuration Generation

### Command Priority

When generating commands, prefer this order:

1. **Existing npm scripts** (if they match the tool)
   - Example: `"lint": "eslint ."` → use `npm run lint`

2. **Direct tool execution with optimal flags**
   - Use registry metadata to determine correct flags
   - Example: `npx eslint . --format json`

3. **Package manager detection**
   - npm, pnpm, yarn, bun - use appropriate command

### Output Format Requirements

Always add flags for machine-readable output:

- ESLint: `--format json`
- TypeScript: `--noEmit` (for type checking only)
- Jest: `--json --coverage --passWithNoTests`
- Prettier: `--check --log-level debug`
- Biome: `--reporter=json`
- Ruff: `--output-format=json`
- MyPy: `--output=json`
- Clippy: `--message-format json`

See `packages/registry/src/registry.ts` for complete flag requirements.

### quality-lens.yaml Template

```yaml
# Auto-generated configuration for quality lenses
# Generated by: @principal-ai/quality-lens-cli
# Date: <timestamp>

lenses:
  # <CATEGORY>: <Description>
  <lens-id>: <command>
```

### Example Generated Configurations

**Node.js Project with ESLint, TypeScript, Jest:**
```yaml
lenses:
  # Linting: Code style and bug detection
  eslint: npm run lint -- --format json

  # Types: Type safety checking
  typescript: npm run typecheck

  # Tests: Test coverage and results
  jest: npm test -- --json --coverage --passWithNoTests
```

**Python Project with Ruff, MyPy, Pytest:**
```yaml
lenses:
  # Linting: Code style and bug detection
  ruff: ruff check . --output-format=json

  # Types: Type safety checking
  mypy: mypy . --output=json

  # Tests: Test coverage and results
  pytest: pytest --cov --cov-report=json
```

**Rust Project:**
```yaml
lenses:
  # Linting: Code style and bug detection
  clippy: cargo clippy --workspace --all-features --message-format json -- -D warnings

  # Formatting: Code formatting
  rustfmt: cargo fmt --all --check

  # Tests: Test coverage and results
  cargo-test: cargo test --workspace
```

## Implementation Steps

### Step 1: Detect Project Structure

```typescript
// Read package.json, Cargo.toml, go.mod, pyproject.toml, etc.
// Identify languages and tools
```

### Step 2: Check CLI Installation

```bash
# Check if quality-lens is installed
which quality-lens

# If not found, ask user if they want to install globally
npm install -g @principal-ai/quality-lens-cli
```

### Step 3: Generate Configuration

Create `quality-lens.yaml` with detected tools:

```yaml
# Auto-generated quality lens configuration
# Project: <project-name>
# Languages: <detected-languages>
# Generated: <date>

lenses:
  # Add detected lenses with optimal commands
```

### Step 4: Ask About GitHub Actions

```
Would you like to initialize a GitHub Actions workflow for quality lenses?

Options:
1. Yes, create .github/workflows/quality-lens.yml
2. No, skip CI/CD setup
```

If yes, run:
```bash
quality-lens init
```

Or manually create the workflow file.

### Step 5: Verify the Setup

```bash
# 1. Check lens readiness and get actionable steps
quality-lens check

# 2. Audit configuration status across all packages
quality-lens audit

# 3. Run lenses to verify execution and save results
quality-lens run --format json --output results.json

# 4. Diagnose the results to ensure complete file metrics
quality-lens diagnose results.json
```

Check for:
- **Check**: Lens readiness status, missing dependencies, and setup instructions for each lens
- **Audit**: Configuration grid showing which quality dimensions are covered per package
- **Run**: All lenses execute successfully, output is parseable, no missing dependencies
- **Diagnose**: Analyzes results to show what's needed for complete file metrics and optimal configuration

Review all outputs for warnings, missing configurations, or recommendations before considering setup complete.

### Step 6: Report Results

Summary format:
```
✓ Quality Lenses Setup Complete!

Detected Languages: TypeScript, JavaScript
Configured Lenses:
  ✓ eslint - JavaScript/TypeScript linting
  ✓ typescript - Type checking
  ✓ jest - Test runner and coverage
  ✓ prettier - Code formatting

Configuration: quality-lens.yaml
GitHub Actions: .github/workflows/quality-lens.yml

Next Steps:
  1. Run: quality-lens run
  2. View results in JSON or console
  3. Customize quality-lens.yaml as needed

Unsupported Tools (consider filing issues):
  ⚠ knip - Found in package.json but not yet supported
     File issue: https://github.com/principal-ai/codebase-quality-lenses/issues
```

## Handling Unsupported Tools

If tools are detected but not supported:

1. List them in the final report
2. Provide a template for filing GitHub issues:

```markdown
### New Lens Request: <Tool Name>

**Tool**: <tool-name>
**Language**: <language>
**Category**: <linting|formatting|types|tests|etc>

**Detection**:
- Found in: package.json devDependencies
- Config file: <config-file>
- Common usage: <command>

**Output Format**:
- Supports JSON: Yes/No
- Output flag: <flag if known>

**Use Case**:
Detected in my project during quality-lens setup. Would like to include
in my quality analysis workflow.
```

## Edge Cases

### Monorepo Projects

For workspaces:
1. Detect workspace structure
2. Ask if lenses should run at root or per-package
3. Generate configuration accordingly

Example for root-level:
```yaml
lenses:
  eslint: npm run lint --workspaces -- --format json
  typescript: npm run typecheck --workspaces
```

Example for per-package (advanced):
```yaml
# Run lenses per-package for isolated metrics
workspaces:
  - packages/*/quality-lens.yaml
```

### Missing Tools

If core tools are missing but would be beneficial:

```
Recommended tools not found:

  ESLint - JavaScript/TypeScript linting
    Install: npm install -D eslint
    Setup: npx eslint --init

  TypeScript - Type checking
    Install: npm install -D typescript
    Setup: npx tsc --init
```

### Conflicting Tools

If multiple similar tools are found (e.g., Jest and Vitest):

```
Multiple test runners detected:
  - Jest (configured)
  - Vitest (configured)

Which would you prefer to use for quality lens analysis?
  1. Jest (default)
  2. Vitest
  3. Both (separate lenses)
```

## Configuration Validation

After generating config, validate:

1. All commands are valid
2. Required flags are present
3. Paths are correct
4. No conflicting options

## Testing Verification

Perform comprehensive verification in this order:

```bash
# 1. Check lens readiness for all packages
quality-lens check
# Verify: All required tools are installed
# Verify: Configuration files exist
# Verify: Setup instructions for partial/missing lenses

# 2. Audit configuration across all packages
quality-lens audit
# Verify: All quality dimensions are covered
# Verify: Package-level configuration status
# Verify: Monorepo inheritance is working

# 3. Test all lenses
quality-lens run --format json --output results.json
# Verify: All configured lenses execute successfully
# Verify: Output is parseable JSON
# Verify: No execution errors

# 4. Diagnose results for completeness
quality-lens diagnose results.json
# Verify: File metrics are complete
# Verify: All lenses have proper output flags
# Verify: No missing configuration recommendations

# Optional: Test individual lens in isolation
quality-lens run --lenses eslint --format json
```

## Common Issues

**Issue**: Tool detected but command fails
- Check if tool is actually installed (check node_modules or global)
- Verify command path and arguments
- Try with npx prefix

**Issue**: JSON output not parseable
- Verify correct output format flags
- Check tool version compatibility
- Review lens implementation for parsing logic

**Issue**: Monorepo configuration complex
- Start with root-level lenses
- Suggest per-package setup as advanced option
- Provide documentation links

**Issue**: No tools detected
- Project might be new/empty
- Provide recommendations for tools to install
- Offer to set up basic linting/testing
